# WatchBridge 0.1.0-alpha.5

## macOS builds

The same codebase now produces macOS applications alongside the Windows build:

| Asset | Architecture | Notes |
| --- | --- | --- |
| `WatchBridge-0.1.0-alpha.5-arm64.dmg` | Apple Silicon | Native arm64 build |
| `WatchBridge-0.1.0-alpha.5-x86_64.dmg` | Intel | Native x86_64 build |

Both images contain `WatchBridge.app`, built from the same sources as the Windows
binary. The macOS build talks to the device through the system `usbmuxd` socket,
so no driver or Apple Mobile Device Service is required.

The bundle is **ad-hoc signed**, not signed with a Developer ID and not
notarized. Apple Silicon refuses to execute unsigned binaries, which is why the
build signs it, but Gatekeeper still treats a downloaded copy as untrusted. After
copying the app to `/Applications`, clear the quarantine flag once:

```bash
xattr -dr com.apple.quarantine /Applications/WatchBridge.app
```

Without that step macOS reports the app as damaged. Distributing to other people
without that warning would require a Developer ID certificate and notarization.

One feature is unavailable on macOS: automatic renewal's "start at login" option
is implemented through the Windows registry, so the control reports that it is
unavailable. Renewal itself works while the app is running.

## Windows build

Unchanged packaging: `watchbridge-windows.zip` contains the executable plus its
build report and checksums.

| File | Contents |
| --- | --- |
| `WatchBridge.exe` | The application, unsigned; SmartScreen warns on first run |
| `BUILD.json` | Source commit, whether the tree was dirty, lockfile hashes, toolchain versions, SHA-256 of the executable |
| `SHA256SUMS.txt` | Checksums of the files above |
| `LICENSES.zip` | Third-party licence texts plus a dependency inventory |

The Windows build targets Windows 10 22H2 and Windows 11 on x64 and requires the
WebView2 runtime, which ships with Windows 11 and must be installed separately on
Windows 10.

## Notes

- The licence of the signing dependency `apple-codesign-quick` is still being
  clarified; see `docs/LICENSE_REVIEW.md`.
- `Auth error -23782` during sign-in means the selected anisette server reports
  an old macOS version; pick a server that reports 13.x.
- One paired Watch per iPhone; only IPAs that contain both the iPhone host and
  `Watch/*.app` are supported.
- The macOS build has not been through physical device validation; the Windows
  build's validation record is unchanged.
