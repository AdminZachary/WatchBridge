# WatchBridge 0.1.0-alpha.5

## macOS build

macOS applications are now produced as well, without requiring Xcode:

| Asset | Architecture | Notes |
| --- | --- | --- |
| `WatchBridge-0.1.0-alpha.5-arm64.dmg` | Apple Silicon | Native arm64 build |
| `WatchBridge-0.1.0-alpha.5-x86_64.dmg` | Intel | Native x86_64 build |

Both images contain `WatchBridge.app`, built from the same sources as the Windows
binary. The macOS build talks to the device through the system `usbmuxd` socket,
so no driver or Apple Mobile Device Service is required.

The bundle is **ad-hoc signed**, not signed with a Developer ID and not
notarized. Apple Silicon refuses to execute unsigned binaries, which is why the
build signs it, but Gatekeeper still treats a downloaded copy as untrusted. The
first launch is blocked; allow it once in **System Settings → Privacy & Security
→ Open Anyway**, then open the app again. Distributing to other people without
that prompt would require a Developer ID certificate and notarization.

One feature is unavailable on macOS: automatic renewal's "start at login" option
is implemented through the Windows registry, so the control reports that it is
unavailable. Renewal itself works while the app is running.

## Notes

- The licence of the signing dependency `apple-codesign-quick` is still being
  clarified; see `docs/LICENSE_REVIEW.md`.
- `Auth error -23782` during sign-in means the selected anisette server reports
  an old macOS version; pick a server that reports 13.x.
- One paired Watch per iPhone; only IPAs that contain both the iPhone host and
  `Watch/*.app` are supported.
- The macOS build has been validated on a physical Apple Silicon Mac; the Windows
  build's validation record is unchanged.
- The Windows build is unchanged and attached as `watchbridge-windows.zip`.
