# WatchBridge 0.1.4

Four sign-in fixes. Two of them unblock users who could not get past the Apple ID
step at all. This release addresses #9, #10 and #11 — thanks to everyone who sent
logs, they made both bugs visible.

## What changed

- **Sign-in no longer assumes the trusted phone number is id `1`.** The SMS step always started with a hardcoded number id, so accounts whose trusted number had another id were rejected by Apple before any code was sent. The app now uses the id Apple reports, and if Apple answers with a challenge for a different number it retries once with that one.
- **A failed phone-number lookup no longer blocks trusted-device sign-in.** The number list is only needed for the SMS fallback, but the login treated a failure as fatal. Accounts that answer `403` for that lookup can now complete the trusted-device prompt instead of being stopped before it appears.
- **Certificate errors explain themselves.** Previously the raw Developer Portal error was shown, so "at the limit" and "a request that was never completed" looked identical. Each case now has its own message: certificate limit, unfinished request (usually expires within 24 hours), and a certificate that does not belong to the team.

## Requirements

**Windows** — Windows 10 22H2 or Windows 11 on x64, Apple Mobile Device Service (iTunes or the Apple Devices app) and the WebView2 runtime.

**macOS** — macOS 11 or newer on Apple Silicon or Intel, without Xcode.

**Linux** — the `usbmuxd` daemon, WebKitGTK 4.1, a Secret Service keyring and xdg-desktop-portal. GNOME and KDE provide the last two by default.

All three need an iPhone already paired with the target Watch, and a cable for the preparation step.

## Installing on Linux

```bash
sudo apt install ./WatchBridge_0.1.4_amd64.deb    # Debian/Ubuntu
sudo dnf install ./WatchBridge-0.1.4-1.x86_64.rpm # Fedora
sudo systemctl enable --now usbmuxd
watchbridge
```

## Installing on macOS

The bundle is ad-hoc signed but not notarized. The first launch is blocked by Gatekeeper: allow it once under **System Settings → Privacy & Security → Open Anyway**, then open the app again.

## Known limitations

- The Windows executable is unsigned, so SmartScreen warns on first run; the macOS bundle is not notarized.
- Automatic renewal's "start at login" option is Windows-only.
- One paired Watch per iPhone. Only IPAs that contain both the iPhone host and `Watch/*.app` are supported.
- The signing dependency `apple-codesign-quick` does not declare a licence; see `docs/LICENSE_REVIEW.md`.
